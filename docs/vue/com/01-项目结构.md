# 项目结构

本系列用一个小型 monorepo 练习组件开发：`components` 放组件，`utils` 放共享的类型与注入键，`play` 提供预览页面。这里只描述示例组件项目；当前博客仓库本身是 Docusaurus 项目，不需要改成 Vue 项目。

如果只练习一两个组件，直接放在单个 Vue 项目的 `src/components` 下即可。拆包的价值是明确依赖和导出边界，不是目录越多越好。

## 创建预览项目

官方推荐使用 [create-vue](https://vuejs.org/guide/quick-start.html) 创建基于 Vite 的项目。当前快速开始要求 Node.js `^22.18.0 || >=24.12.0`；建议使用满足要求、仍受支持的 LTS 版本，并按项目锁文件固定依赖。

在一个新的示例目录中执行：

```bash
pnpm create vue@latest play
```

交互选项选择 TypeScript，其他功能按需启用。编辑器使用官方推荐的 **Vue - Official** 扩展。以下目录和配置是最小示例，不是已经发布的 `@welkin-ui` 包。

```text
├── package.json
├── pnpm-workspace.yaml
├── pnpm-lock.yaml
├── packages
│   ├── components
│   │   ├── package.json
│   │   └── src
│   │       ├── index.ts
│   │       ├── Row.vue
│   │       └── Col.vue
│   └── utils
│       ├── package.json
│       └── src
│           └── index.ts
└── play
    ├── package.json
    ├── vite.config.ts
    └── src
        ├── main.ts
        └── App.vue
```

## Workspace 与包引用

根目录的 `pnpm-workspace.yaml` 定义工作区范围：

```yaml title="pnpm-workspace.yaml"
packages:
  - 'packages/*'
  - 'play'
```

根目录负责转发命令，不需要把所有包的依赖都装到这里：

```json title="根目录 package.json"
{
  "name": "welkin-ui-workspace",
  "private": true,
  "scripts": {
    "start": "pnpm --filter @welkin-ui/play dev",
    "build:play": "pnpm --filter @welkin-ui/play build"
  }
}
```

`--filter` 匹配的是包名；需要把 create-vue 生成的 `play/package.json` 的 `name` 改为 `@welkin-ui/play`。以下片段合并到已有文件中，保留脚手架生成的 scripts、Vue 和 Vite 等依赖：

```json title="play/package.json 的补充字段"
{
  "name": "@welkin-ui/play",
  "dependencies": {
    "@welkin-ui/components": "workspace:*"
  }
}
```

组件包直接导出源码，供预览项目编译：

```json title="packages/components/package.json"
{
  "name": "@welkin-ui/components",
  "private": true,
  "type": "module",
  "exports": { ".": "./src/index.ts" },
  "dependencies": { "@welkin-ui/utils": "workspace:*" },
  "peerDependencies": { "vue": "^3.5.0" }
}
```

```json title="packages/utils/package.json"
{
  "name": "@welkin-ui/utils",
  "private": true,
  "type": "module",
  "exports": { ".": "./src/index.ts" },
  "peerDependencies": { "vue": "^3.5.0" }
}
```

`workspace:*` 要求从本地工作区解析同名包，避免意外使用注册表中的同名依赖。`utils/src/index.ts` 的注入键定义见[布局组件](./02-layout-com.mdx)。配置完成、组件文件补齐后，在根目录执行：

```bash
pnpm install
pnpm start
```

工作区链接本身不会编译 `.vue` 或 `.ts`。运行时的转换由消费者的构建工具负责。相关规则见 [pnpm Workspace](https://pnpm.io/workspaces) 与[过滤命令](https://pnpm.io/filtering)。

## SFC 是怎样运行的

`@vitejs/plugin-vue` 接入 SFC 编译流程：拆分 `<template>`、`<script>`、`<style>`，将模板编译为渲染函数，把脚本与样式交给后续构建流程。浏览器最终执行 JavaScript，而不是直接执行 `.vue` 文件。

Vue 3.2.13 起可以通过 `vue/compiler-sfc` 使用随 Vue 提供的编译器；常规 Vite 应用由插件处理，不需要在业务代码中调用它。直接使用 `@vue/compiler-sfc` 编写工具时，应保持编译器与 Vue 运行时版本一致。Node 对未知扩展名的错误只是缺少转换流程的一种表现，不是 SFC 不能运行。

组件包的导出入口如下：

```ts title="packages/components/src/index.ts"
export { default as newRow } from './Row.vue'
export { default as newCol } from './Col.vue'
```

预览项目即可局部使用它们，无需全局注册：

```html title="play/src/App.vue"
<script setup lang="ts">
import { newRow, newCol } from '@welkin-ui/components'
</script>

<template>
  <newRow :gap="16">
    <newCol :base="12">左侧</newCol>
    <newCol :base="12">右侧</newCol>
  </newRow>
</template>
```

Vite 主要负责转换与打包，TypeScript 转换不等于类型检查。使用脚手架生成的 `type-check` 脚本（通常调用 `vue-tsc`），并确认它覆盖工作区的组件源码。工具选择见[官方 TypeScript 指南](https://vuejs.org/guide/typescript/overview.html)。

## 从本地练习到组件库发布

本系列的包设置了 `private: true`，用于本地练习。如果要发布，需要额外完成：

1. 使用 [Vite library mode](https://vite.dev/guide/build.html#library-mode) 编译组件，将 `exports` 指向构建产物，并保留按需导入入口。
2. 把 Vue 设为 peer dependency，并在打包配置中 externalize `vue`，让组件和应用共享同一份运行时。
3. 生成 `.d.ts`，导出公共类型；明确 CSS 的入口，以及消费者是否需要额外导入样式。
4. 检查包的 `files`、`exports` 和样式副作用配置，用打包产物在独立项目中验证，而不仅在 workspace 中导入源码。

构建目标不同，配置也不同：预览应用产出页面资源，组件库产出供其他项目使用的模块。不能把预览应用的构建结果直接当作组件库发布。
