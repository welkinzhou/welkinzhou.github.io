[前面](./2026-08-12.md#agentic-rag)计划让助手在查文档以外执行操作。读数据可以直接返回结果，发邮件会影响外部世界，需要先让用户核对收件人和正文。我给这类写操作加了暂停和恢复。

## interrupt

假设知识库助手收到“把这份报告发给同事”。它可以先查资料、整理邮件，但发送会产生外部影响，必须等用户确认。缺收件人或正文时先补齐信息；字段齐全后展示待执行内容，确认前不调用发信服务。

哪些工具需要停下来，不能让模型自己声明。工具目录中的定义把所属 Agent、权限和确认要求放在一起，例如邮件工具：

```python
ToolDefinition(
    "send_email",
    "action",
    "tool:email:send",
    requires_confirmation=True,
)
```

模型提出调用后，执行层先看这个定义。读知识库不用弹确认，发送邮件必须先产生待确认项。这样新增工具时也能明确它属于哪个子图、由谁授权。

[LangGraph 的 `interrupt()`](https://docs.langchain.com/oss/python/langgraph/interrupts) 会把节点状态交给 checkpointer 保存，并等待外部输入。恢复时要沿用同一个 `thread_id`，用 `Command(resume=...)` 把用户决定交回图；节点会从开头重跑，所以副作用应放在 interrupt 之后，暂停前的外部调用也要能安全重跑。下面展示必要结构，是 API 示意，不是可直接运行的完整程序：

```python
from langgraph.checkpoint.memory import InMemorySaver
from langgraph.graph import START, StateGraph
from langgraph.types import Command, interrupt

def send_email(state):
    decision = interrupt({"to": state.to, "body": state.body})
    if not decision["approved"]:
        return {"status": "rejected"}
    email_service.send(to=state.to, body=state.body)
    return {"status": "sent"}

graph = StateGraph(State).add_node("send_email", send_email)
graph.add_edge(START, "send_email")
app = graph.compile(checkpointer=InMemorySaver())
config = {"configurable": {"thread_id": "conversation-123"}}
pending = app.invoke(input_state, config)  # 到 interrupt() 时暂停
result = app.invoke(Command(resume={"approved": True}), config)
```

本项目这里采用应用自己的快照恢复流程，不是 LangGraph 原生 `interrupt()`。快照保存未决 Action、运行状态和已完成调用；恢复时先核对归属与权限，再决定是否继续。核心顺序可以概括为下面的流程伪代码：

```text
snapshot = load_pending_snapshot(conversation)
if snapshot.actor_or_tenant != current_actor or snapshot.conversation != current_conversation:
    reject_resume()
if not permission_allows(snapshot.pending_action):
    reject_resume()
if decision == "拒绝":
    finish_as_rejected()
else:
    restore_run_and_action(snapshot)
    skip_recorded_calls()
    execute_only_unfinished_action()
```

快照不能当成可信命令；新消息会清掉旧的未决操作。用户拒绝后结束这次操作，不能因为模型曾生成“已完成”就写成成功。应用层只续跑未完成的 Action，不能把这套状态管理等同于 LangGraph 的检查点或 `interrupt()`。

## 执行结果

工具的执行结果要区分权限不足、超时、没有证据和服务出错。读到当前用户信息，或拿到一个看起来完整的工具参数，都不代表邮件已经发出。只有实际写调用成功，回答里才能说操作完成。

我也给工具调用加了次数与时限，避免模型在失败后一直重试。知识库检索本身仍是读操作，但加入 Agent 图后，它和其他工具一样需要受租户、资源和总预算约束。下一步是让文档的审核、发布也有同样清楚的边界。
