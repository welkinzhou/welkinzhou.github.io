## Agent loop

如果你调用过 OpenAI 或者 Anthropic 的接口，就会发现 AI 辅助，真的是在聊天。以 OpenAI 为例，这是它官网的[示例](https://developers.openai.com/api/docs/quickstart)：

```python
from openai import OpenAI

client = OpenAI()

stream = client.responses.create(
    model="gpt-5.6",
    input=[
        {
            "role": "user",
            "content": "Say 'double bubble bath' ten times fast.",
        },
    ],
    stream=True,
)

for event in stream:
    print(event)

```

`create` 中就是我们传给模型的内容，`input` 是对话列表。模型会分析我们传入的内容，给出合理的回答。我们所有的努力都是为了让模型的回答更准确。最有效的办法是提升模型能力，这部分主要由大模型开发公司提供。我个人感受，提升还是很明显的。一年前，幻觉是很常见的东西，系统提示词中需要加入大量幻觉约束。现在的模型都加入 RL 做大量训练，指令遵循能力大幅提升。但是这方面离我们普通开发人员有些距离，我们的工作更专注于辅助模型工作，也就是 Harness。

我们先从基础链路开始。我们需要给模型一个设定，也就是 `system prompt`。同样是看病，医生和患者的想法肯定不同，我们需要模型从合理的视角看问题。在 OpenAI 中使用 `instructions` 字段，或者 `role = developer` 的 message。这部分提示词会一直存在，优先级最高。

接着我们需要增加模型对现状的感知。模型是根据语料训练出来的，这些语料可能是数月或数年前的。模型并不知道当下，发生了什么。我们需要补充情况，包括相关知识和如何获取知识的途径（tools）。tools 是规范。比如，提问今天天气如何，模型不知道今天是什么时候，用户人在哪里，就会根据内部知识库随机给出答案。如果拥有了 tools，模型就会返回工具调用，来获取当前时间，查询位置，最后查询天气。

一个标准工作流程如下，用户提出问题，服务器收到问题，把用户的问题包装成模型调用接口规范的 message，再加入系统提示词，工具集，传递给模型。模型收到问题，规划是否需要使用工具，还是直接给出答案。需要使用工具，服务器调用工具，把工具返回结果按照工具 id 加入 messages，再次传递给模型，开启下一轮推理。反复执行提问 --> [推理 --> 工具调用 --> 推理] --> 结束推理 --> 下一个问题。方括号圈起来的可能会有多轮，也就是常说的 agent loop。

## LangChain 和 LangGraph

上述的功能完全可以用一个死循环完成，完全手写会很麻烦。LangChain 相关是有一整套生态的，辅助开发，暂时会用到的就是 LangChain 和 LangGraph。LangChain 提供的功能会更基础，我们会用它组成一条流水线，包括输入、解析到输出。看下[示例代码](https://docs.langchain.com/oss/python/langchain/quickstart)：

```python
import urllib.error
import urllib.request

from langchain.agents import create_agent
from langchain.chat_models import init_chat_model
from langchain.tools import tool
from langgraph.checkpoint.memory import InMemorySaver

SYSTEM_PROMPT = """You are a literary data assistant.

## Capabilities

- `fetch_text_from_url`: loads document text from a URL into the conversation.
Do not guess line counts or positions—ground them in tool results from the saved file."""


@tool
def fetch_text_from_url(url: str) -> str:
    """Fetch the document from a URL.
    """
    req = urllib.request.Request(
        url,
        headers={"User-Agent": "Mozilla/5.0 (compatible; quickstart-research/1.0)"},
    )
    try:
        with urllib.request.urlopen(req, timeout=120) as resp:
            raw = resp.read()
    except urllib.error.URLError as e:
        return f"Fetch failed: {e}"
    text = raw.decode("utf-8", errors="replace")
    return text


model = init_chat_model(
    "gemini-3.1-pro-preview",
    model_provider="google-genai",
    temperature=0.5,
    timeout=600,
    max_tokens=25000,
    streaming=True,
)

checkpointer = InMemorySaver()

agent = create_agent(
    model=model,
    tools=[fetch_text_from_url],
    system_prompt=SYSTEM_PROMPT,
    checkpointer=checkpointer,
)

content = f"""Project Gutenberg hosts a full plain-text copy of F. Scott Fitzgerald's The Great Gatsby.
URL: https://www.gutenberg.org/files/64317/64317-0.txt

Answer as much as you can:

1) How many lines in the complete Gutenberg file contain the substring `Gatsby` (count lines, not occurrences within a line, each line ends with a line break).
2) The 1-based line number of the first line in the file that contains `Daisy`.
3) A two-sentence neutral synopsis.

Do your best on (1) and (2). If at any point you realize you cannot **verify** an exact answer with
your available tools and reasoning, do not fabricate numbers: use `null` for that field and spell out
the limitation in `how_you_computed_counts`. If you encounter any errors please report what the error was and what the error message was."""

agent_result = agent.invoke(
    {"messages": [{"role": "user", "content": content}]},
    config={"configurable": {"thread_id": "great-gatsby-lc"}},
)

print(agent_result["messages"][-1].content_blocks)
```

`fetch_text_from_url` 是使用 tool 装饰器定义的工具。模型理解工具不是通过读代码，而是查看描述。我们需要构造一个对象，存储工具功能描述和参数描述。@tool 装饰的工具，重点不是函数体，而是注释 `Fetch the document from a URL`，大模型通过这个理解工具功能。模型推理到需要调用这个工具，就会返回 tool call，我们拿到返回手动调用 tool。模型不关注函数体，也就是说，你的实现和描述南辕北辙，模型也不知道（反面教材）。`init_chat_model` 会创建 model 对象，调用 model 的 invoke 方法，就可以和 AI 进行对话了。这里是创建了一个 agent，agent 在 LangChain 中是 model + loop，会自动执行 model 返回的 tool calls，直到模型表示推理结束。checkpointer 是存储过往对话历史的地方，`InMemorySaver` 也就是说对话历史保存在内存中，关机后就没有了。这一套代码，就是一个完全可跑的小功能。

如果没有 LangChain，我们需要手写工具集描述对象，加一个工具集的映射（消息返回时，根据映射调用 tool），还需要自己实现 agent loop。LangChain 的功能就是提供模型/工具/提示词等积木，通过 pipe 链接起来就成为了一个 workflow。Agent 底层是跑在 LangGraph 伤的，LangGraph 负责用 LangChain 提供的积木或者工具等，编排复杂业务流程。可以把 LangGraph 看成 DAG，不过中间会有一些循环，不过我们还是需要防止无限循环，最终这个图还是要从开始走向结束。

### LangChain 基本功能

#### loader

除了向大模型发文，我们还可能给模型提供各种文档，优化模型回答。此时需要加载各种文档，LangChain 提供了各种 [loder](https://docs.langchain.com/oss/python/integrations/document_loaders) 加载不同类型资源。

例如，Unstructured loader（Unstructured python 库，可以加载多种文档）:

```python
from langchain_unstructured import UnstructuredLoader

file_paths = [
    "./example_data/layout-parser-paper.pdf",
    "./example_data/state_of_the_union.txt",
]

loader = UnstructuredLoader(file_paths)

docs = loader.load()
```

#### Text splitter

单个文件内容太多，一次性发送给模型会超出上下文限制，需要对文本切割分批发送。切片还有好处，当个文本块语义更聚合，可以进行向量化。每次发问前，检索向量，找到符合度最高的一起传递给模型。

最常用的就是 `RecursiveCharacterTextSplitter`，它会按照给定分隔符，默认 `["\n\n", "\n", " ", ""]`，对进行递归分割。可以设定 `chunk_size` 和 `chunk_overlap`。chunk_size 是切片大小，不超过这个大小的情况下切块。当前的章节文本，没几句就换行分段了。如果严格按照分隔符切，文章会切的很碎。RecursiveCharacterTextSplitter 会在保证不超过 chunk_size 的前提下，把多个片段放在一起。那如果单个文本块很长，一个就超过 chunk_size 怎么办？RecursiveCharacterTextSplitter 会把这样的文本块，切成多个片段，每个片段间文本重叠，重叠的长度就是 chunk_overlap。这样能在一个大段切成多个小段时，确保语义连贯。

```python
from langchain_text_splitters import RecursiveCharacterTextSplitter

# Load example document
with open("state_of_the_union.txt") as f:
    state_of_the_union = f.read()

text_splitter = RecursiveCharacterTextSplitter(
    # Set a really small chunk size, just to show.
    chunk_size=100,
    chunk_overlap=20,
    length_function=len, # 长度计算方法，也可以使用 token 计算
    is_separator_regex=False,
)
texts = text_splitter.create_documents([state_of_the_union])
print(texts[0])
print(texts[1])
```

from langchain_openai import ChatOpenAI

#### tool

tool 的实现上面已经有了例子，官方有一些推荐的 [tools](https://docs.langchain.com/oss/python/integrations/tools)。createAgent 是做了封装的功能，基础使用可以用 `bind_tools`。

```python
from langchain_openai import ChatOpenAI

@tool
def add(a: int, b: int) -> int:
  """Add two integers."""
  return a + b

model = ChatOpenAI(model="gpt-4o")
model_with_tools = model.bind_tools([add])

# 手动执行一次调用
response = model_with_tools.invoke("What is 3 plus 5?")
```

#### chain

这个并不是一个孤立概念，有些细碎功能，懒得一一举例了，都放在这里。LangChain 有个 [runnable 概念](https://reference.langchain.com/python/langchain-core/runnables/base/Runnable)，runnable 可以自己手写，官方提供的 model 等组件都是 runnable。可以使用 `|` 或者 pipe 方法，将这些组件组装成一条 chain，如：

```python
from langchain_deepseek import ChatDeepSeek
from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate

# 加载环境变量
import os
from dotenv import load_dotenv

load_dotenv()

template = ChatPromptTemplate(
    [
        ("system", "You are a helpful AI bot. Your name is {name}."),
        ("human", "Hello, how are you doing?"),
        ("ai", "I'm doing well, thanks!"),
        ("human", "{user_input}"),
    ]
)


llm = ChatDeepSeek(
    model="deepseek-v4-flash",
    temperature=0,
    max_tokens=None,
    timeout=None,
    max_retries=2,
    # other params...
)

chain = template | llm | StrOutputParser()

result = chain.invoke(
    {
        "name": "Bob",
        "user_input": "What is your name?",
    }
)

print(result)
```

在上面，我把提示词模版（template）、model（llm）和输出格式化（StrOutputParser）组合了起来，变成了一条 chain，这条 chain 还是可以使用 invoke 方法。

自定义 Runnable，需要用到 `RunnableLambda`：

```python
from langchain_core.runnables import RunnableLambda

# A RunnableSequence constructed using the `|` operator
sequence = RunnableLambda(lambda x: x + 1) | RunnableLambda(lambda x: x * 2)
sequence.invoke(1)  # 4
sequence.batch([1, 2, 3])  # [4, 6, 8]

# A sequence that contains a RunnableParallel constructed using a dict literal
sequence = RunnableLambda(lambda x: x + 1) | {
    "mul_2": RunnableLambda(lambda x: x * 2),
    "mul_5": RunnableLambda(lambda x: x * 5),
}
sequence.invoke(1)  # {'mul_2': 4, 'mul_5': 10}
```

自定义的 Runnable 也可以加入 chain，Runnable 可以使用 `|` 串行执行，还是可以使用 `{}` 并行执行。

### LangGraph

LangChain 已经能让我们把不同功能组合到一起了，小的功能已经可以跑了。有些任务不是一次性的，比如 agent loop，需要重复调用 tool，或者需要增加条件判断，比如简单任务直接调用 llm 回答，业务关联问题，需要检索，单纯的 chain 就很难搞了。LangGraph 会把业务编排成图，可以实现条件判断、循环等。

下面是官方示例，如何实现一个 agent loop：

```python
from langchain.tools import tool
from langchain_deepseek import ChatDeepSeek

from langchain.messages import SystemMessage
from langchain.messages import AnyMessage, ToolMessage
from typing import Literal
from typing_extensions import TypedDict, Annotated
from langgraph.graph import StateGraph, START, END

import operator

from dotenv import load_dotenv

load_dotenv()

model = ChatDeepSeek(model="deepseek-v4-flash", temperature=0)

# 工具
@tool
def multiply(a: int, b: int) -> int:
    """Multiply `a` and `b`.

    Args:
        a: First int
        b: Second int
    """
    return a * b


@tool
def add(a: int, b: int) -> int:
    """Adds `a` and `b`.

    Args:
        a: First int
        b: Second int
    """
    return a + b


@tool
def divide(a: int, b: int) -> float:
    """Divide `a` and `b`.

    Args:
        a: First int
        b: Second int
    """
    return a / b


tools = [add, multiply, divide]
tools_by_name = {tool.name: tool for tool in tools}
model_with_tools = model.bind_tools(tools)

# graph 共享的数据
class MessagesState(TypedDict):
    messages: Annotated[list[AnyMessage], operator.add]
    llm_calls: int


# 调用数据
def llm_call(state: MessagesState):
    """LLM decides whether to call a tool or not"""

    return {
        "messages": [
            model_with_tools.invoke(
                [
                    SystemMessage(
                        content="You are a helpful assistant tasked with performing arithmetic on a set of inputs."
                    )
                ]
                + state["messages"]
            )
        ],
        "llm_calls": state.get("llm_calls", 0) + 1,
    }


def tool_node(state: MessagesState):
    """Performs the tool call"""
    result = []
    last_message = state["messages"][-1]
    tool_calls = getattr(last_message, "tool_calls", [])
    for tool_call in tool_calls:
        tool = tools_by_name[tool_call["name"]]
        observation = tool.invoke(tool_call["args"])
        result.append(ToolMessage(content=observation, tool_call_id=tool_call["id"]))
    return {"messages": result}


def should_continue(state: MessagesState):
    """Decide if we should continue the loop or stop based upon whether the LLM made a tool call"""
    messages = state["messages"]
    last_message = messages[-1]
    tool_calls = getattr(last_message, "tool_calls", None)

    # 如果有工具调用，跑工具
    if tool_calls:
        return "tool_node"

    # 否则，停止（回复用户）
    return END


# Build workflow
agent_builder = StateGraph(MessagesState)

# Add nodes
agent_builder.add_node("llm_call", llm_call)
agent_builder.add_node("tool_node", tool_node)

# Add edges to connect nodes
agent_builder.add_edge(START, "llm_call")
agent_builder.add_conditional_edges("llm_call", should_continue, ["tool_node", END])
agent_builder.add_edge("tool_node", "llm_call")

# Compile the agent
agent = agent_builder.compile()

# Show the agent
from IPython.display import Image, display

png_bytes = agent.get_graph(xray=True).draw_mermaid_png()

# 保存到文件
with open("graph.png", "wb") as f:
    f.write(png_bytes)

print("图片已保存到 graph.png")

# Invoke
from langchain.messages import HumanMessage

messages: list[AnyMessage] = [HumanMessage(content="Add 3 and 4.")]
initial_state: MessagesState = {"messages": messages, "llm_calls": 0}
result = agent.invoke(initial_state)
for m in result["messages"]:
    m.pretty_print()

```

`MessagesState`是一个全图共享的数据，构建图之前，我们应该想清楚需要哪些数据。`messages`，对话历史记录肯定是要共享的。调用模型需要把历史对话记录全部传过去，tool 调用需要获取 tool 信息，结束要打印最终回答。`llm_calls`，模型调用次数。大模型可能陷入死循环，调用次数用来限定循环上限，这里是没加判断，实际上是需要的。`agent_builder = StateGraph(MessagesState)` 创建了一个图。

LangGraph 中有 node（节点） 的概念，默认有 START 和 END 两个节点，中间如何连接由我们定义。添加了两个节点，`llm_call` 和 `tool_node`，`add_node` 第一个参数是节点名，第二个是节点功能的实现，LangGraph 通过节点名索引到指定功能。接着添加了一条边，`agent_builder.add_edge(START, "llm_call")`，开始之后就会走到 llm_call 节点，进行模型调用。接着添加条件边，`agent_builder.add_conditional_edges("llm_call", should_continue, ["tool_node", END])`。llm_call 是前继节点，llm_call 执行完成后就会进入条件判断方法 should_continue。should_continue 需要返回节点名称。`["tool_node", END]` 是节点映射集合，在这里也可以省略，因为和图中定义名称一样。假设 should_continue 需要用到多处，和业务强相关，就有可能返回的名称和当前图不匹配，此时需要通过第三个参数重新映射：

```python
agent.add_node('a', node_a)
agent.add_node('b', node_b)

def common_continue(state: MessagesState):
    """通用判断逻辑"""
    messages = state["messages"]
    last_message = messages[-1]

    # 是否复杂任务
    if is_complex(last_message):
        return "complex"

    # 简单任务
    return 'simple'
  
agent.add_conditional_edges("llm_call", common_continue, {"complex": "node_a", "simple": "node_b"})
```

上面功能就是判断任务是否复杂，不同情况跑不同流程，这个可能用到很多处，路由名最好还是根据功能取，使用时再按照图节点重定义映射。可以看到，如果使用 `add_conditional_edges`，重新把下一个节点指向自身或者上游节点，就可以实现循环。

除了这种方式，还可以使用 `Command`：

```python
def router_node(state: State) -> Command[Literal["node_a", "node_b", "__end__"]]:
    """节点内部决定下一步，同时更新状态"""
    
    if state["score"] > 0.8:
        return Command(
            update={"status": "high"},      # ← 更新共享状态
            goto="node_a"                   # ← 动态路由到 node_a
        )
    elif state["score"] > 0.3:
        return Command(update={"status": "medium"}, goto="node_b")
    else:
        return Command(update={"status": "low"}, goto=END)
```

Command 可以做条件判断，更灵活。注意添加过条件边，就不要在节点内部使用 Command，会出新多条路径。
