# 文档处理方案

我之前把还原文档和语义切割混在一起考虑，越想越乱。这次拆成两步：保留原文结构，再生成检索用的块。

原文按章节保存，不受切片预算限制；交给模型的内容要控制长度。两步分开，处理边界就清楚了。

以下面结构为例：

```markdown
# 第一章 RAG

这是第一章介绍。

## 1.1 RAG 是什么

RAG 是……

## 1.2 RAG 架构

RAG 包含……

### 1.2.1 Retriever

Retriever......

### 1.2.2 Generator

Generator......

### 1.2.3 Reranker

Reranker......
```

按长度硬切，单独拿到一个 chunk，看不出它在讲哪部分：

```markdown
// chunk 1
# 第一章 RAG
这是第一章
// chunk 2
介绍。
## 1.1 RAG 是什么
// chunk 2
是什么
RAG 是……
```

按标题切，又会遇到章节长短不一、层级嵌套的问题。我先用树保存这些关系，再处理切片大小。

## 自然结构还原

之前习惯按聊天来想文档。聊天可以讲完 A、B、C，再回头讲 A，把每段当成独立话题也没什么问题。

文章有标题层级，正文和子章节都从属于标题。我得先保留这层关系。

我用三个类描述文档：`Document` 代表文件，`Section` 保存章节树，`Block` 保存 Markdown 元素。

### Document

Document 关联原文件，Section 保存解析内容。原文件仍放在 MinIO，重建文档时按结构拼接 section。

```python
@dataclass
class Document:
    id: str
    # 文档基本信息
    title: str
    filename: str
    # 原始文件信息
    file_type: str
    source_object_key: str
    # 解析后的 Markdown
    parsed_object_key: str | None = None
    # 文档结构
    sections: list["Section"] = field(default_factory=list)
    # 文档级元数据
    metadata: dict[str, Any] = field(default_factory=dict)
```

### Section

Section 保存当前标题和正文，子 Section 单独挂在树里，不重复放进正文。这里保留完整内容，不限制长度。

Section 类型如下：

```python
@dataclass
class Section:
    id: str
    document_id: str
    # 层级
    level: int
    # 标题
    title: str
    parent_id: str | None = None
    children: list["Section"] = field(default_factory=list)
    section_path: list[str] = field(default_factory=list)
    blocks: list[Block] = field(default_factory=list)
    metadata: dict[str, Any] = field(default_factory=dict)
```

section_path 标记章节路径，方便 search 工具定位。解析层级出错时，可以调整 level。

### Block

类型如下：

```python
from dataclasses import dataclass, field
from enum import Enum
from typing import Any


class BlockType(str, Enum):
    PARAGRAPH = "paragraph"
    LIST = "list"
    TABLE = "table"
    IMAGE = "image"
    CODE = "code"
    FORMULA = "formula"
    QUOTE = "quote"


@dataclass
class Block:
    id: str
    # 内容类型
    type: BlockType
    # 当前 Block 的原始/标准化内容
    content: str
    # 来源定位
    page_start: int | None = None
    page_end: int | None = None
    # 在原始解析结果中的位置
    index: int = 0
    # 类型相关的扩展信息
    metadata: dict[str, Any] = field(default_factory=dict)
```

## 语义块

父子块的用途见[《RAG 系统五》](./2026-08-06.md#上下文设计)。这里解决生成方式：从 section 树构造父块，再切子块。

单个 section 足够大，就形成父块；内容不足，就按文档顺序合并。比如父块预算 3000，h1 正文 500，下面两个 h2 各 1200，合起来 2900。

沿标题树递归合并，超预算后还得退回上一层。我更愿意先展平 section，再按顺序处理。

展平后的文本保留结构信息，用来构造父块。类型如下：

```python
class ChunkType(str, Enum):
    PARENT = "parent"
    CHILD = "child"


@dataclass
class ParentChunk:
    id: str
    document_id: str

    type: ChunkType = ChunkType.PARENT

    content: str = ""

    section_ids: list[str] = field(default_factory=list)
    section_path: list[str] = field(default_factory=list)

    page_start: int | None = None
    page_end: int | None = None

    token_count: int = 0

    metadata: dict[str, Any] = field(default_factory=dict)
    
@dataclass
class ChildChunk:
    id: str
    parent_id: str
    document_id: str

    type: ChunkType = ChunkType.CHILD

    content: str = ""

    section_id: str | None = None
    section_path: list[str] = field(default_factory=list)

    page_start: int | None = None
    page_end: int | None = None

    token_count: int = 0

    metadata: dict[str, Any] = field(default_factory=dict)
```

父块预算 3000、子块预算 500，展平结果如下：

```python
Section 1 # 300
Section 1-1 # 1200
Section 1-2 # 1400
Section 1-3 # 1400
Section 2 # 300
```

`300 + 1200 + 1400 = 2900`，前三个 section 合成父块，1-3 另起一块。

很短的标题不必固定为切割边界，避免切得太碎。

```
H1
 └── Parent 永远不能跨

H2
 └── 尽量不要跨，但必要时可以

H3/H4
 └── 尽量合并
```

父块边界确定后，拼接对应 section 的内容，再切子块。
