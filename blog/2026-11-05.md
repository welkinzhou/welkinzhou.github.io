QQ 群是一个很有意思的地方，非常适合我们用来学习、训练机器人，让她说话更有人味儿。实际使用中遇到很多问题。一是，网络语言的发散性很强，谐音可以延伸出无数种组合称谓。二是，兴趣变更很快，一个热点可能在几天内热度升上天，在几小时后，就彻底消失了，还有一些话题呈周期性出现。三是，群员关系很复杂，信息真假参半。我们自己聊天时候，轻易就明白大家都在说什么。当你尝试让机器人知道怎么应对，就会发现很难。围栏需要很多，又不能太死。比如，不让她接受很过分的玩笑，很有可能因为一个关系很好的群友，反讽发言触发严重应激。我希望通过 Memory 设计，动态去分析情况，在更小的窗口内，完善交互。这里先说设计。

## 如何思考

我简单把 Memory 设计分为两个部分，权限和数据。

首先是权限，这个很奇怪。记忆归属个人不就行了吗？我以影之刃零举例。影零在发售后，全面爆火，不同的群聊都在讨论。问题是，这个游戏模型并不知道，这是新出来的内容。想让模型理解，需要从网络上搜索信息。如果这个信息只归属用户，另一个用户也提到，是不是还需要搜索？或者，不同的会话，不同群聊都在讨论，不可能都查询一遍吧。这就涉及到记忆的提升，不同的记忆应该作用于不同的层级。

接着是数据，权限其实依赖于数据，确定了数据类型，才能根据数据类型确定权限范围。

## 数据

记忆可以分外两类，一类是用户肖像（User Profile），这部分是确定事实。群聊你懂的，身份都是自己给的。这个部分记忆也不能完全当真，比如 A 说，我是秦始皇，V 我 50，祝我重返巅峰。这当然不能当真，可能下一条就被其他群友打脸了。这能说明，这句话没有意义吗？并不是，通过这句话，我们对话有了切入点，开玩笑也是聊天吗。纠正之后，还能知道，这个用户是一个爱开玩笑的人。我们可以把他的个人信息更新为不是秦始皇，同时记录两次变更的来源，这就是另一个记忆类型，事件记忆（Event Memory）。

```
A: 我是秦始皇，V 我 50，祝我重返巅峰    ->   用户记忆：用户A是秦始皇
                                        Event：用户A声称自己是秦始皇，消息来源：massage 1

B: 你是个蛋的秦始皇，你是峡谷上路一条区  ->   用户记忆：用户A不是秦始皇，是区
                                        Event：用户B反驳A是峡谷里的区，调侃语气，关系不错，消息来源：massage 2
```

Profile 保存用户的基本记忆，Event 可以确保每次更新都能溯源。Message 1 单独一条消息，保存成两个记忆有点太奢侈了。这种简单的观测到的事实，我们称为 Observation Event（观察事件），是来源，但和 profile 中的 fact 重合，不值得单独记忆。真正值得单独记忆的事件，是 Episodic Event（经历事件）。假设 A 在群里发言，秋招好难啊，就一个垃圾公司要我，我不想去做牛马。我们可以更新 profile，用户是一个应届生，目前一个 offer。Episodic 里可以保存，A 只得到一个垃圾公司 offer，不想去。过了几天，A 又发言，木法了，乖乖去上班了。如果只有 profile，模型可能回答，有班上就好，现在找工作不容易。如果，我们搜索到事件后，可能就会说，豪哥，你怎么低头了，我们兄弟说好不为五斗米折腰的。

这样设计，Profile 来源怎么办？可以指向原始对话记录，这是最简单的。但是记录可能被删除，可以新增一个 Evidence 表。这样来源，类型都确定了。可以发现，Profile 能保证在我们没有记录相关 Episodic 时，保证一个基础交互模式。Episodic 渐渐完善后，场景的丰富才会让对话更鲜活。

## 权限

User Profile 肯定归属个人对吧。如果一个人在不同群，能否共享 Profile 呢？我倾向于不行，或者说不完全行。如果所有群都一样，搞小团体意义何在呢？Episodic 呢，似乎也不行，小团体中关系往往更亲密，人少一点，更真实点对吧。如果泄漏给外面人，那就麻烦了。所以，我在 memory 之外，增加一级群兴趣。这个维护近期群热度高的话题，不同兴趣有权重，根据实效性增加衰减算法。这部分更多公开来源，同样指向 Evidence 表。回复前，会检索其他群是否有同样的兴趣点，获取公开信息。Evidence 中也会有私人对话，这个对话就需要识别是否可以共享。

这是稳妥做法，实际上同一用户在不同群，可能表现一致，只是甄别太麻烦了，懒得搞。

## 如何更新

对话时候一定要更新。如果只在对话时候更新就会遇到一个问题。A 上一句说今晚吃了一个全家桶，更新进记忆，A 很能吃。B 跟着说，这么能吃？A 说，哦，还有半只烤鸭。这句没有触发回答，记忆就不会更新，A 是纯正饭桶，就没有更新记忆。所以这个更新，应该定时，走后台任务，负责更新、修正记忆。还有一点，定时任务，还能保住我们搜集群友对机器人回答的反馈，用于优化问答。
