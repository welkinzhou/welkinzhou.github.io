生成问答集时，需要给出题模型足够的上下文，才能写出需要综合相邻内容的问题。设想一个文档刚完成新版本发布，旧版本的父块仍留在历史记录里；若只按序号取附近内容，模型可能把两代资料拼成一道题。之后重新切片或发布时，这种混合证据尤其难追。

## 证据范围

现在构造证据组时，先固定锚点，再要求候选父块属于同租户、同知识库、同文档、同一 IndexGeneration，只取序号相邻的块。证据预算是整块计算，不截断原文去拼凑一条看似完整的引用。锚点缺失或单块超预算就放弃这题。

因此，候选材料要同时满足身份范围、版本和位置条件。筛选条件在评测服务里直接比较锚点的身份和位置：

```python
if (
    parent.tenant_id == anchor.tenant_id
    and parent.knowledge_base_id == anchor.knowledge_base_id
    and parent.document_id == anchor.document_id
    and parent.index_generation_id == anchor.index_generation_id
    and abs(parent.sequence - anchor.sequence) <= 1
):
    candidates.append(parent)
```

这是筛选逻辑的等价片段。比如锚点位于第 8 块，候选只能来自第 7 至 9 块，且租户、知识库、文档和索引代都要相同。实际实现还会把锚点放在首位，最多选择三个父块，正文总量不超过 12000 字符。超过预算时不截断父块，因为 `quote` 一旦被截掉，后面的逐字核验就失去依据；锚点不存在或锚点本身超过预算则整题跳过。

预算选择也按完整父块进行。伪代码保留锚点、依次尝试最近的相邻块，放不下就跳过该块，不切掉正文尾部：

```python
if anchor not in candidates or len(anchor.content) > 12_000:
    return []

selected = [anchor]
size = len(anchor.content)
for parent in nearest_neighbors(candidates, anchor):
    if len(selected) == 3:
        break
    if size + len(parent.content) <= 12_000:
        selected.append(parent)  # 保留原块，不截断
        size += len(parent.content)
```

锚点不可缺席：若它不存在或单独就超过上限，就不能形成这道题的证据组。相邻块预算不够时只是不选该块，不会把部分文本拼给模型。

模型生成的引用还要逐项核对：父块 ID 必须在这组材料里，引用文字必须逐字存在，答案的断言要有相应证据。综合题确实需要两个以上来源，不能把单段事实题贴上“综合”标签。生成时的来源代会记入样本；评测集建立后，即使新的文档版本发布，也不会悄悄改写旧题的来源。

## 来源回溯

这次修正不直接提高检索分数，它让评测题的依据更一致。样本保存 `source_chunk_ids` 和 `index_generation_id`，据此定位当初的父块及索引代。历史父块保留时还能回看原文；清理历史代后，正文可能已经删除，ID 只能说明来源位置，不能恢复原文，也不能重新核对当时的逐字引用。问答、代 ID 和 chunk ID 继续留在记录里，回看旧分数时要记住这个边界。

到这里，[标题参与关键词检索](./2026-09-12.md)、发布代隔离和问答集证据已经连上：先保证被检索的是正确版本，再用可追溯的问题判断改动是否有效。
