[评测问题集](./2026-09-03.md)可以从父块反向生成。题量上来后，我发现“模型能出题”不代表题目值得用：来源太短、答案靠常识补全、同一问题换个说法重复出现，都会让评测看起来稳定，实际却测不到检索差异。

## 候选证据

生成结果不能只保存问题和参考答案，还要能指出答案依据哪段资料。生成时按文档轮流抽父块，过滤过短内容，并让模型同时给出问题、参考答案和逐字证据。每条证据包含父块 ID 与原文中的引用片段。程序先核对引用确实存在、证据包含锚点父块、跨片段综合题确实用了多个来源，再交给裁判模型检查问题是否独立、答案是否有依据以及题型是否匹配。

一条候选题的结构大致如下，`parent_id` 与 `quote` 都必须能在本次给模型的父块中核对：

```json
{
  "question": "差旅报销需要哪些材料？",
  "reference": "需要发票和申请单。",
  "question_type": "fact",
  "evidence_quotes": [
    {"parent_id": "来源父块 ID", "quote": "报销需发票与申请单。"}
  ]
}
```

结构只是候选输入，程序还要把它与本次允许的父块集合逐项比对。下面是省略字段清洗和日志的校验伪代码：

```python
allowed = {p.parent_id: p for p in evidence_group}
source_ids = {item.parent_id for item in candidate.evidence_quotes}

valid = anchor.parent_id in source_ids
valid &= all(
    item.parent_id in allowed
    and item.quote.strip()
    and item.quote in allowed[item.parent_id].content
    for item in candidate.evidence_quotes
)
valid &= candidate.question_type != "synthesis" or len(source_ids) >= 2
valid &= normalize(candidate.question) not in normalized_existing_questions
```

`parent_id` 必须属于允许集合，`quote` 必须逐字出现在对应父块中；候选证据要包含锚点父块，综合题还要有两个以上来源，规范化后的问题不能与已有题重复。程序检查通过后，裁判模型再判断问题是否独立、答案是否受证据支持、题型是否匹配；自动判断也不能替代人工审核业务价值。任一硬条件失败就丢掉候选，再看同锚点的下一题。

同一锚点可以生成多个候选，但最终只留通过检查的一题。已有问题会先规范化再去重，避免标点和大小写变化逃过检查。候选材料不足时返回空，不为了凑满请求数量编造题目。生成数量也受合格父块数约束，不能把“要求 100 条”当成一定能产出 100 条。

## 人工审核

自动检查能挡住一部分明显错误，不能代替人工看答案是否对业务有意义。样本除了题目和答案，还要保留来源父块 ID、知识库、租户和索引代；这些信息分别用于定位原文、确认资源范围和识别资料版本。新样本进入待审核状态；只有没有待审核项且至少有一条通过，才能运行评测。后面即使文档重建，也能知道这道题当初根据哪份资料生成。

这也是为什么生成数量和可用父块数要分开。申请 20 条，如果只有 12 个合格父块，系统应按实际容量限制请求，而不是让模型从同一段资料反复改写凑满 20 条。评测集需要覆盖不同文档和题型，重复题只会把某一个局部问题的影响放大。

这一步比盲目扩大 Golden Set 更有用。问题集的依据不稳，后续比较[标题权重](./2026-09-12.md)或切片大小，分数变化也难解释。
