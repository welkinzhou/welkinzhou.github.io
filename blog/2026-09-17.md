例如知识库问答里，用户会看到回答逐字出现，也会关心 Agent 正在检索，或为什么发信操作停下来等确认。若前端只收到一段文本，这些状态就无从呈现；若前后端各自约定事件格式，刷新后恢复确认也容易对不上。[已有聊天图](./2026-09-05.md)支持检索、工具调用和确认恢复，我把入口统一为 AG-UI 事件流。

## Run

前端提交 `RunAgentInput`，后端以 run 为单位处理去重和会话锁，再用 SSE 发出运行、文本、工具调用和 interrupt 事件。协议把这些信息拆成有类型的事件，前端可以按事件更新界面，而不是从文本里猜状态。下面是本项目服务层映射出的事件形态；具体字段以 [AG-UI 事件文档](https://docs.ag-ui.com/concepts/events)为准：

```text
RUN_STARTED(threadId, runId)
TEXT_MESSAGE_START(messageId)
TEXT_MESSAGE_CONTENT(messageId, delta)
TOOL_CALL_START(toolCallId, toolCallName)
TOOL_CALL_ARGS(toolCallId, delta)
TOOL_CALL_END(toolCallId)
RUN_FINISHED(outcome={type: interrupt, interrupts: [...]})
```

事件名称来自 AG-UI，下面的消费逻辑是伪代码，展示前端怎样按 ID 归并增量并恢复确认卡片：

```text
onEvent(event):
  if event.type == TEXT_MESSAGE_START:
    messages[event.messageId] = ""
  if event.type == TEXT_MESSAGE_CONTENT:
    messages[event.messageId] += event.delta
  if event.type == TOOL_CALL_START:
    tools[event.toolCallId] = {name: event.toolCallName, args: ""}
  if event.type == TOOL_CALL_ARGS:
    tools[event.toolCallId].args += event.delta
  if event.type == RUN_FINISHED and event.outcome.type == "interrupt":
    showConfirmation(event.outcome.interrupts)
```

`messageId` 和 `toolCallId` 让并行消息与工具调用各自归并，不会把参数混进回答文本。等待用户确认时，run 以 interrupt 结果结束，前端显示待处理操作。刷新后可以查询同一会话尚未处理的确认项，让卡片与服务端等待的任务对上。

入口不再要求前端解析一套私有聊天流。HTTP 层接收标准输入，再把服务层编码的事件作为 SSE 返回：

```python
@router.post("/welkin")
async def run_welkin_agent(
    body: RunAgentInput,
    user: CurrentActor,
    service: AgUiService,
):
    prepared = await service.prepare_run(body, actor=user)
    return StreamingResponse(
        service.stream_encoded(prepared),
        media_type="text/event-stream",
    )
```

上面省略了 FastAPI 的用户依赖和 `chat:use` 权限声明，完整入口仍先鉴权。`prepare_run` 用 `thread_id` 找会话，用 `run_id` 识别本轮；相同请求重试时复用已有运行记录，新的运行则取得会话锁。

迁移时，前端还得按事件顺序维护运行状态：文字增量进入回答，工具事件进入执行轨迹，暂停事件显示待确认操作，完成或失败事件关闭这一轮。后端的阶段、计划和来源信息放在 `welkin.*` 自定义事件里，不把模型的内部推理文本当成用户可见回答。

例如页面刷新后有一张未确认的发信卡片，前端通过 `GET /api/v1/agents/welkin/{thread_id}/interrupt` 取回。没有待确认项时接口返回 204；取回卡片只恢复展示，不等于已经同意执行。只有用户明确确认并恢复 run，Action 才会继续处理，这和上一阶段的[确认约束](./2026-09-05.md)一致。

## 会话并发

同一会话并发提交两轮，很容易出现晚完成的旧轮覆盖新状态。服务层持有覆盖单轮时限的会话锁，run 标识用于去重。AG-UI 解决的是传输和状态对齐，不能代替工具权限和执行结果检查；确认前的暂停与恢复仍按[上一阶段的约束](./2026-09-05.md)处理。
