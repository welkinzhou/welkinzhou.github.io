[文档切片](./2026-08-19.md)把标题和正文分开后，父块保留章节名，子块只放正文。一开始关键词和向量检索都只查不含标题的 `content`，关键词检索效果很差。标题分离改善了块的结构，也要求 BM25 明确查标题字段。

## BM25

很多问题直接使用章节名、产品名或术语名，正文却可能只写“它”“这个流程”。标题与正文分离后，BM25 只搜正文会丢掉词面上最明确的线索。向量检索仍可能靠语义找到一部分内容，但不能指望它补齐所有精确名称。

我保留了字段分离，只调整两条检索通路的输入：Milvus 的 Embedding 仍只用子块正文；Elasticsearch 把 `title` 和 `content` 分别建为文本字段，BM25 同时查询，并给标题更高的权重。当前查询使用 `title^2.5` 与 `content`，索引分词为 `ik_max_word`，查询分词为 `ik_smart`。

```json
{
  "multi_match": {
    "query": "用户问题",
    "fields": ["title^2.5", "content"]
  }
}
```

入库时，ES 的 `title` 存当前节标题，`content` 存子块正文；查询时 `title^2.5` 只提高标题命中的 BM25 权重。Milvus 的向量仍由 `[child.content for child in children]` 生成，不会因为这个查询改动自动包含标题。

命中后，系统把向量与 BM25 两路结果做 RRF 融合、重排，再回到父块取较完整的内容给模型。标题用于词面召回，不必硬塞回每个 Embedding 输入。这还保留了两路检索的差异：精确名称交给关键词，正文含义交给向量。

## 评测变化

我当时遇到过一次很极端的评测：四项指标低到不足 0.1；把标题加入关键词检索后，同一批题的结果升到约 0.9。这个观察促使我保留标题字段并提高它的检索权重。对应的原始报告、样本和运行环境没有留在仓库里，所以这里记录的是那次调试结果，不能把 0.9 当成所有知识库都能达到的分数。

这次也提醒我：切片字段的变化会影响索引语义。只改查询而不重建旧代，历史数据未必有独立的标题字段。比较前后效果时，要确认测试命中的是按新结构构建并已发布的索引代。
