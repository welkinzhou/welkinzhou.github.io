最近 OpenClaw 很火，有种 agent 飞入寻常百姓家的感觉。我想整理一下自己的 AI 使用体验，确定接下来学什么。重点还是 LLM 的推理能力，以及怎么给它提供合适的信息。

<!-- truncate -->

我更关心怎么用好模型的**推理能力**。训练模型离普通开发者有些远，我能动手的主要是调用和工程部分。模型拿到了什么信息，也会影响它的判断。

推荐读一下 [Tracing the thoughts of a large language model](https://www.anthropic.com/research/tracing-thoughts-language-model)。看完能多了解一些模型的推理过程。

这篇是学习笔记，夹着一点胡思乱想。以后回头看，大概能发现不少错误，发现了再改。Act, don't explain，也是我学到的第一课。

## LLM 能力

模型经过训练，学到了大量知识。我暂时把它回答问题的方式理解成两类：利用**已知结果**，或根据相关信息做**关联推理**。

拿相声里的“缸比盆深，盆比碗深，碗比碟子深”举例。问缸和碟子哪个深，模型可能直接给出熟悉的答案，也可能沿着这些关系推下去。表面上答案一样，我关心的是它依据了什么信息。

我更在意传给模型的信息对不对。输入错了，推理也可能走偏。人与人争论也有点像这样：双方拿到的事实不同，光讲道理很难说服对方。

模型给出答案，不代表它真的核对过。要求它展示推理过程，也不能保证推理正确。信息不全时，它可能拼出一条看着合理的推理链，这就是我担心的**幻觉**。使用时还是要核对依据。

## 使用 AI 的重点

我能控制的是上下文：传什么、保留什么、缺什么再去查。窗口有限，优先放和当前任务有关的信息。Prompt、Rules、Tools 都可以从这里理解。

系统提示词交代模型的角色和基本要求。对话越来越长，这些要求仍然要保留，不能随着旧消息一起丢掉。

Rules 保存项目规范，团队可以共用，也不用每次重新说明。加载哪些规则，要看当前任务。

Prompt 和 Rules 主要说明我要什么，Tools 提供获取信息和执行操作的手段。比如查询文件、搜索资料。工具返回的结果会影响后续判断，得保证它可信。

问“今天天气怎么样”，模型需要知道今天的日期、用户的位置和当地天气，这些信息不能只靠训练时的知识补齐。工具可以逐步查询，再把结果交给模型。我们提供的不只是一个回答要求，还要提供获得依据的途径。

### 如何编写

GitHub 上的 [system-prompts-and-models-of-ai-tools](https://github.com/x1xhlol/system-prompts-and-models-of-ai-tools) 收集了很多 AI 工具的 prompt。我觉得 prompt 和 rules 没那么大的区别，最终都是写给模型看的指令。

我更愿意用简洁的描述讲清角色，不写成“熟悉 Vue、React……”的简历。明确指定某个技术，模型会倾向于使用它；只给领域定位，是希望它自己选择方案。这是我目前的想法，还要继续试。

角色还决定从哪个角度看问题。同样讨论看病，医生和患者关注的内容不同。给出角色，是为了让模型围绕这次任务的视角组织信息。

接着看 Cursor 的提示词：

```
You are an AI coding assistant, powered by GPT-4.1. You operate in Cursor.

You are pair programming with a USER to solve their coding task. Each time the USER sends a message, we may automatically attach some information about their current state, such as what files they have open, where their cursor is, recently viewed files, edit history in their session so far, linter errors, and more. This information may or may not be relevant to the coding task, it is up for you to decide.

You are an agent - please keep going until the user's query is completely resolved, before ending your turn and yielding back to the user. Only terminate your turn when you are sure that the problem is solved. Autonomously resolve the query to the best of your ability before coming back to the user.

Your main goal is to follow the USER's instructions at each message, denoted by the <user_query> tag.

Tool results and user messages may include <system_reminder> tags. These <system_reminder> tags contain useful information and reminders. Please heed them, but don't mention them in your response to the user.
```

这段先交代角色，再提醒模型：用户输入和工具结果都可能有用，也可能有误。模型要判断相关性，不能把收到的内容全当成可靠依据。我使用 AI 时也得注意这一点，发现输入有问题就及时纠正。

### 上下文管理

Prompt、Rules、Skills 都占上下文，不必每次全加载。按任务拆分、需要时再读，能省掉无关内容。

搜索工具和 RAG 把资料留在外面，需要时再取。窗口足够大、**也不在乎 token 费用**，还可以把整本书和完整对话直接传给模型。选哪种方式，要看实际限制。

Skill 把一套做法存下来，Subagent 负责独立处理任务。我想用它们减少主对话里的无关信息，具体实现留到后面。
