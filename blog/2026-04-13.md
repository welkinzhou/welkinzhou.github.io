## State 管理

复杂任务执行到一半，程序异常或用户改了想法，不应该只能重启。前面已经完成的几步可能仍然有效，从头再来既浪费时间，也丢了执行进度。我用 `LoopState` 保存当前情况，为恢复和中途调整提供依据。状态管理本身不能解决全部问题，但后续处理必须先知道程序走到哪里。基础模型如下：

```python
@dataclass
class LoopState:
    messages: list  # 历史消息
    turn_count: int = 1  # 循环次数
    transition_reason: str | None = None  # 继续循环原因
```

`transition_reason` 记录这一轮继续或退出的原因，比如模型要求继续、程序异常、用户修改输入。`messages` 记录对话和内部状态消息，内部消息不一定传给模型。程序根据这些信息决定下一步。

## Tool context

之前的 ToolRegistry 已经隔离了工具集：

```python
class ToolUseContext:
    def __init__(self):
        self.handlers = {}
        self.permission_context = {}
        self.mcp_clients = {}
        self.messages = []
        self.app_state = {}
        self.notifications = []
```

还要隔离运行环境。比如子 agent 只能操作指定目录，任务完成后再通知主 agent。
程序按任务创建执行环境，调用工具时找到对应环境：

```python
def route_tool(tool_name: str, tool_input: dict, ctx: ToolUseContext):
    if tool_name.startswith("mcp__"):
        # 找到 mcp 工具执行环境
        return run_mcp_tool(tool_name, tool_input, ctx)
    return run_native_tool(tool_name, tool_input, ctx)
```

工具调度也要分情况。read_file 等只读操作可以并发；多个工具修改同一个文件，要按顺序执行。

```python
def is_concurrency_safe(tool_name: str) -> bool:
    """检查工具是否并发安全"""
    # 并发安全工具列表
    concurrency_safe_tools = ["read_file", "search_files"]
    return tool_name in concurrency_safe_tools
```

先检查并发是否安全，再分批执行。

```python
batches = partition_tool_calls(tool_uses)

for batch in batches:
    if batch["is_concurrency_safe"]:
        run_concurrently(batch["blocks"])
    else:
        run_serially(batch["blocks"])

```
